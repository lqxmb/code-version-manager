# Code Version Manager（工作空间版本管理）

Python 3 + GTK 3 桌面 Git 管理器，支持任意工作空间、本地离线发布、分支开发、手动目录合并、ZIP 导出和 SSH 整仓同步。

## 一条清晰的开发流程

以 main 的 `v0.0.3` 为例：

1. 先切换到当前检出的 `main`，再在版本历史选择 `v0.0.3`，点击“新建分支”，输入 `branch1` 并确认基线。只能从 main 新建开发分支。
2. branch1 独立发布 `branch1/v0.0.3-beta.0.0.1`、`...2`、`...3`。main 可同时发布 `v0.0.4`、`v0.0.5`、`v0.0.6`，开发分支基线始终是 0.0.3。
3. 点击“合并到 main”。确认框显示最新 beta、目标 main 正式版本及双方提交。开发分支有晚于最新 beta 的提交时，先发布新的 beta。
4. 合并直接打开 Beyond Compare、Meld 或 KDiff3。左侧为 beta 只读副本，右侧为 main 编辑副本；按文件手动同步并保存，关闭对比工具后点击“完成合并”或“取消合并”。
5. **完成合并会把所选结果作为 main 的普通单父提交保存，不执行 Git merge、不发布、不创建任何 Tag。** 确认框默认勾选删除 branch1 及全部 beta 标签，可取消勾选保留。用户之后可另行发布正式版。
6. “删除分支”选择目标后立即删除任意非 main 本地分支及其全部 beta 标签，不要求已合并或正式发布。删除其他分支不要求当前工作区干净；如果删除的是当前分支，仍需先能安全切换到 main。其他 worktree 正在使用的分支不能删除。下一次“同步远程”传播删除。

新建分支也可选择 main 的其他历史正式版本，但必须先检出 main。切换分支要求工作区干净；main 有未提交、暂存或未跟踪修改时，先提交或另行保存这些修改再切换。合并只处理本地状态，不隐式下载或上传；需要以另一端为准时先使用整仓同步。

### 手动目录合并

- 对比使用 beta 与 main 的完整 Git 树，不按 manifest 或 export-ignore 裁剪。特殊文件用只读说明展示，不跟随符号链接。
- 两侧 `.gitignore` 分别按 Git 规则解析并取并集；任一侧忽略的路径都会从两边隐藏，且软件拒绝将其写回。会话开始后忽略规则固定。
- 相同文件、VERSION 和特殊文件受保护；只允许把有差异的普通文件从右侧编辑副本写入 main。未知路径、来源只读副本变化、链接替换和会话并发变化都会被拒绝。
- 副本保存在实际 Git 目录 `code-version-manager/merge-review/`。打开或取消不会改变工作区、暂存区、提交和分支；取消会删除本次对比副本。
- 关闭对比工具后，界面只显示“完成合并”和“取消合并”。完成时会校验会话并创建 main 普通提交；VERSION 保留 main 的原值。
- 完成确认默认勾选清理来源本地分支和全部 beta 标签。完成不会发布版本或创建标签；远程删除由后续“同步远程”传播。

## VERSION 和标签

- main 发布正式标签，例如 `v0.0.7`；根目录 VERSION 自动写为 `0.0.7` 并加入提交、版本清单及 ZIP。
- 开发分支保留创建时继承的 VERSION，例如 `0.0.3`，不写 beta。修改或删除 VERSION 后不能在开发分支发布，应先还原该文件。
- 合并时 VERSION 保留 main 的值，例如 `0.0.6`；只有用户随后发布正式版时才变为 `0.0.7`。
- VERSION 必须为普通文件，不能是符号链接、目录或被 .gitignore 排除。旧的 VERSION 同步开关不再使用。
- 预发布实际 Git 标签为 `branches/branch1/v0.0.3-beta.0.0.3`；界面显示 `branch1/v0.0.3-beta.0.0.3`。分支名含斜线时会 URL 编码。
- 旧 `beta.1` 标签继续可读，新发布只生成 `beta.0.0.N`。旧分支多基线或与 main 没有共同历史时，会提示先检查/整仓同步或新建分支，不自动改名和重写历史。
- Git 标签是仓库级引用。GitHub 的 Tags/Releases 页面仍显示全仓库标签，选择网页分支不会隐藏其他分支的标签。

默认“本分支相关版本”显示本分支版本及可达的正式基线，继承的正式版本只读；“全部分支版本”用于查询其他分支版本。分支列表把本地和 origin 同名分支合成一行，当前分支仅用绿色标识，文字不再添加“当前”，例如 `main（本地+origin）`。

## 整仓同步：明确选择一端作为准本

发布始终仅保存本地，不自动上传。同步前请先核对确认窗口。

| 按钮 | 操作 |
| --- | --- |
| 同步本地 ↓ | 以 origin 为准，覆盖全部本地分支、正式标签和预发布标签 |
| 同步远程 ↑ | 以本地为准，覆盖全部远程分支、正式标签和预发布标签 |

两个方向都包含新增、改写和删除。**来源端没有的目标分支或版本标签也会删除。** 共享正式标签也会统一为来源状态。来源必须有有效 main；非版本标签、其他 remote 和软件恢复引用不参与同步。

软件逐项显示领先、落后、分叉、无共同历史、标签说明变化及将发生的删除。时间、版本号只供核对，不用于自动选择方向。多个分支可能各有独有修改，选择准本意味着接受覆盖清单；适用于明确指定准本的工作方式。

- 两端全部受管引用一致时按钮为绿色并禁用；有差异时可查看清单，无法执行的方向在悬停提示具体原因。
- 每次检查同步状态时一并刷新分支选择器里的 origin 分支；不再有单独的“刷新远程分支”按钮。检查失败会清空远程分支列表。
- 操作前及下载后重新核对引用；上传使用原子推送和精确租约。服务器保护规则仍可能拒绝写入。
- 同步本地前，保存暂存内容、未提交修改和未跟踪文件；可能被覆盖的忽略文件移到恢复目录。完成后可选择恢复修改，恢复冲突时恢复点仍保留。
- 当前分支被来源端删除时切到 main；其他 worktree 占用待更新分支时停止。
- 覆盖前的引用、配置、版本清单及内部 CHANGELOG 保存在本机恢复点。Git 恢复引用位于 `refs/code-version-manager/recovery/`，资料位于实际 Git 目录的 `code-version-manager/recovery/`。
- 远程传输全部 Git 历史，范围不限于 ZIP 或本次勾选文件。同步前确认历史内容适合上传。本地 manifest 不上传，远程版本没有 manifest 时按完整 Git 快照导出。

超时无法确认远程是否已接收更新。不要重新发布同一版本，修复网络后刷新、核对再同步。

## 工作空间与本地发布

- 为普通目录启用独立 Git 仓库，初始分支 main；位于父 Git 仓库中的目录仍可创建独立版本库。
- 最近工作空间最多保存 10 个，可单独移除或清空。默认启动顺序：环境变量 `CODE_VERSION_MANAGER_REPOSITORY`、上次保存目录、`~/catkin_ws`。
- 发布选择器只显示顶层文件和目录，勾选目录递归封装；已删除的顶层范围继续显示并可发布删除。
- 发布使用临时暂存区，保留未选择的已有暂存内容；当前忽略规则排除的历史文件会停止跟踪，本地文件保留。
- 根目录 CHANGELOG.rst 为手写说明输入和下载目标，不纳入新提交、清单或 ZIP。首次发布缺失时补模板，已有内容保留。
- 缺少 .gitignore 时创建 Catkin 构建、日志、缓存、ZIP 等默认规则；已有规则保留并补充根目录 CHANGELOG 忽略项。
- 查看历史版本时禁止误发布；可返回最近工作分支。切换分支及新建分支需要干净工作区，且新建分支只能从当前检出的 main 发起，防止覆盖未跟踪或被忽略文件。

根目录 CHANGELOG.rst 可按以下格式提供发布说明；输入版本号匹配时自动载入，未匹配时保留编辑内容：

```rst
0.0.7 (2026-11-04)
------------------
* 合入 branch1 的开发结果
* 保留 main 的后续修改
```

最终说明以发布窗口内容为准。内部 CHANGELOG 从标签说明生成，修改历史说明不会回写手写文件。

## 比较、导出和历史管理

- 比较两个历史版本的完整目录，或将一个历史版本与可编辑的当前工作区比较。
- 设置中选择 Beyond Compare、Meld、KDiff3，默认 Beyond Compare；对比工具须自行安装。
- Beyond Compare 每次加载内置 BCSessions.xml，历史目录比较按大小比较并排除 `.git`、ZIP、`__pycache__`；手动合并会话使用已过滤的隔离目录，历史输入保持只读。
- 导出完整 ZIP，文件名默认为 `工作空间名_版本号.zip`。有本地 manifest 时按封装清单导出，否则导出完整 Git 树。
- 可查看/下载内部 CHANGELOG、修改标签说明、删除标签；正式标签被其他活动分支共享时禁止单独改写/删除。“删除分支”会删除所选非 main 本地分支及其 beta 标签。
- 删除 main 最新版本及提交会保留当前文件及已有暂存内容。合并和整仓覆盖另有恢复点。
- 元数据位于实际 Git 目录的 `code-version-manager/`，包括 versions 清单、内部 CHANGELOG.rst 和 recovery；不作为工作区文件上传。

## Git 账号与 SSH

“Git 账号”配置唯一 origin SSH 地址、提交姓名、邮箱及推送超时；本地绝对路径也可作为远程用于离线同步。

1. 先创建远程仓库。GitHub 可使用“创建远程仓库（网页）”，创建时不要初始化 README、.gitignore 或许可证。
2. 填写真实 SSH 地址，例如 `git@github.com:<账号>/<仓库>.git`。提交姓名和邮箱记录作者，SSH 密钥决定登录身份。
3. 使用“SSH 公钥设置”复制 .pub 公钥并在服务端授权，也可生成 Ed25519 密钥；已有同名密钥不覆盖，私钥不显示、不上传。
4. 首次连接在终端执行 `ssh -T git@github.com` 并核对官方主机指纹；加密或自定义密钥用 ssh-add 加载。
5. “保存配置”只写本地；“保存并验证连接”执行读取及推送 dry-run，不上传版本。实际覆盖由两个同步按钮确认后执行。

读取和权限预检查限时 120 秒；传输默认 15 分钟，可设置 1–60 分钟。超时会清理本次传输子进程，保留本地版本和恢复点。读取成功不代表写入权限或正式推送一定通过。

## 开发、构建与安装

软件发行版本以本项目 VERSION 文件为准，不等同于工作空间的正式或 beta 标签。

```bash
# 完整测试和语法检查
python3 -m unittest discover -s tests -p 'test*.py'
python3 -m py_compile src/code_version_manager.py

# 只在隔离副本和临时远程中验证指定工作空间
python3 tests/verify_workspace_copy.py ~/branch_testing

# 从源码运行
python3 src/code_version_manager.py

# 生成 dist/code-version-manager_<VERSION>_all.deb
sh build_deb.sh

# 重装
sudo apt install --reinstall ./dist/code-version-manager_$(cat VERSION)_all.deb

# 先退出正在运行的软件，再安装或升级
sudo apt install ./dist/code-version-manager_$(cat VERSION)_all.deb
```

完整依赖与故障排查见 [INSTALL.md](INSTALL.md)。安装后从应用菜单打开 Code Version Manager，或执行 `code-version-manager`。

# Code Version Manager（工作空间版本管理）

独立的 Git 图形版本管理器，可管理任意工作空间，支持本地离线发布和远程仓库同步。

主要功能：

- 为尚未使用 Git 的目录启用版本管理
- 工作空间位于其他 Git 仓库内时，仍可创建独立版本库
- 记录最近打开的 10 个工作空间，可从标题栏快速切换或清空记录
- 首次启用时只显示工作空间第一层，勾选目录会递归封装其内容
- 发布后续版本时同样只显示第一层，并记录所选目录内的删除
- 发布版本时自行勾选要封装的文件
- 配置 Git 提交姓名、邮箱、远程仓库和 HTTPS 账号/访问令牌，或使用已有 SSH 密钥
- 发布后自动同步当前分支的完整提交历史和全部版本标签，也可手动点击“同步远程”
- 远程同步失败时保留本地版本；离线累积多个版本后，下次发布或手动同步会一次补齐
- 支持 `v0.0.1`、`v1.7.8.5`、`v1.7.8.9.7` 等多段版本号
- 版本历史按多段版本号从新到旧排序，不受文件日期影响
- 查看版本历史和版本标签
- 手动修改已发布版本的修改说明，并同步更新 Git 标签和 CHANGELOG
- 使用 Beyond Compare 比较两个完整版本目录
- 选择一个历史版本，使用 Beyond Compare 与完整当前工作空间比较并修改当前文件
- Beyond Compare 每次比较都加载软件内置的 `BCSessions.xml` 默认配置：按文件大小比较、关闭时间戳和内容快速比较、启用 Unicode 规范化，排除 `.git`、`*.zip` 和 `__pycache__`，目录树默认折叠
- 任意选择一个历史版本并下载为 ZIP，默认文件名为 `工作空间名_版本号.zip`（如 `m9_ws_v1.2.0.zip`）
- 删除所选版本标签，不改写提交历史或删除工作空间文件
- 删除 main 的最新版本及 Git 提交，分支退回上一提交并保留文件为当前修改
- 在窗口底部显示当前 Git 增量版本历史占用的磁盘空间
- 查看或下载自动生成的版本管理 `CHANGELOG.rst`，查看窗口支持一键最大化和还原
- CHANGELOG 使用标准 RST 标题格式，每行改动自动输出为 `* 内容`
- 工具元数据保存在 `.git/code-version-manager/`，不会污染工作空间根目录
- 在历史版本状态下阻止误提交
- 通过窗口标题栏的“关于”按钮查看当前软件版本

## Git 账号与远程同步

1. 在 GitHub、Gitee、GitLab 或其他 Git 服务上先创建远程仓库，建议使用没有初始化 README 的空仓库，并确保账号具有写入权限。GitHub 可以直接点击“Git 账号”中的“创建远程仓库（网页）”，在官方网页登录并确认创建。
2. 打开工作空间，点击标题栏的“Git 账号”，填写仓库地址、提交姓名和邮箱。
3. 长期使用同一台电脑推荐 SSH。GitHub 地址可点击“改用 SSH（推荐）”转换，再点击“SSH 公钥设置”复制本机公钥并添加到 GitHub，用户名和访问令牌可留空。HTTPS 方式仍支持 Git 用户名和有仓库写入权限的 PAT/访问令牌；已配置的系统凭据助手也可使用。
4. 勾选“发布版本后自动同步”，点击“验证连接与推送”。本地已有提交时会先执行不上传版本的推送预检查；也可以只保存配置，离线发布版本，稍后再连接远程。

提交姓名和邮箱是提交作者信息，不等同于托管平台登录凭据。远程仓库地址只表示上传位置，不代表已经登录。公开仓库可能允许匿名读取；已有本地提交时，“验证连接与推送”会读取仓库并执行 Git 推送 dry-run，以提前发现登录或写入权限错误，但不会上传提交或标签。预检查通过不代表分支保护规则或服务端钩子一定允许正式同步。空仓库或检出历史提交时，界面会明确提示只检查了读取权限。
仓库地址和非敏感账号信息保存在当前工作空间的 Git 本地配置中，不修改其他仓库或全局 Git 配置。保存远程配置会将当前仓库的 `origin` 指向填写的地址，并清除旧的单独推送地址；其他远程不受影响。未启用版本管理的工作空间会先创建独立仓库，再发布首个版本。

访问令牌仅保留在本次软件会话内，不写入 Git 配置、工作空间文件或系统凭据助手。重启软件后需重新输入；不填写令牌时可以使用系统已有的 Git 凭据助手。配置同一账号时，令牌留空会沿用本次令牌，勾选“清除本次会话中已有的访问令牌”可以清除。SSH 密钥需要提前解锁，软件不会弹出终端密码提示。仅支持加密网络传输，不接受带账号或密码的 HTTPS 仓库地址。

没有已有系统凭据时，HTTPS 同步需要填写 Git 用户名和 PAT/访问令牌，不能只填写仓库地址。同步发现凭据缺失或失效时，会弹出“登录 Git 并重试同步”，输入后只重试远程操作，不重复创建本地版本。选择“稍后同步”会保留所有本地版本，下次可以继续登录并补同步；新凭据仍然失败时停止重试并显示原因，不会反复弹窗。

GitHub 返回 `403` 或 `Permission to ... denied to ...` 时，通常是当前凭据没有仓库写权限，不是本地版本损坏。Fine-grained PAT 请设置 `Resource owner` 为仓库所属者、`Repository access` 选择 `Only select repositories` 并勾选目标仓库，再将 `Repository permissions → Contents` 设为 `Read and write`。令牌所属账号本身也必须具有该仓库写入权限；组织仓库还可能要求审批或 SSO 授权。软件中的“创建 GitHub 写入令牌”链接会预填拥有者和 Contents 写权限，但仍须在 GitHub 页面手动选中目标仓库。生成或调整令牌后，在“Git 账号”中替换旧令牌，再点“验证连接与推送”或“同步远程”；不需要重新发布本地版本。

### 推荐：SSH 免令牌同步

GitHub 已不支持通过网站登录密码执行 Git 推送，不能简单把“访问令牌”改为“账号密码”。使用 SSH 时无需访问令牌：网站账号密码只在 GitHub 官方网页中登录，Git 传输使用本机私钥验证。网站登录与 Git SSH 授权是两件事。

1. 如果已有 SSH 密钥，点击“SSH 公钥设置”选择并复制 `.pub` 公钥，在打开的 GitHub 页面中选择 `Authentication Key`、粘贴并保存。软件只读取公钥，不读取、上传或创建私钥，也不自动改写 SSH 配置。
2. 没有密钥时，先在终端执行 `ssh-keygen -t ed25519 -C "你的邮箱"`，设置密钥口令；如果文件已存在，请使用新文件名，不要覆盖。通过 `ssh-add ~/.ssh/id_ed25519` 解锁所选私钥（自定义路径请相应修改）。
3. 在终端运行 `ssh -T git@github.com`，首次连接时核对 GitHub 官方 SSH 主机指纹后再确认，不能禁用主机检查。显示 `Hi <账号>! You've successfully authenticated` 表示 SSH 身份验证成功；这条测试命令通常返回退出码 1，不代表认证失败。
4. 在“Git 账号”中将地址设为 `git@github.com:lqxmb/code-version-manager.git`，或使用“改用 SSH（推荐）”。此按钮只修改输入框并清空输入框中的令牌，保存后才改变当前仓库的远程配置；不会覆盖其他平台或自定义 SSH 主机别名。
5. 点击“验证连接与推送”，通过后点击“同步远程”。公钥未授权时会显示专门的 SSH 说明，而不会要求输入 PAT。密钥必须属于有目标仓库写入权限的账号。

如果出现 GitHub `401 Bad credentials` 或 `Invalid username or token`，当前 HTTPS 凭据无效；可能已失效、被撤销或输入有误。不要反复重试无效令牌。已发到聊天或日志的令牌应撤销并更换，不要发送私钥。

### 远程还没有仓库

“创建远程仓库（网页）”会根据地址预填 GitHub 仓库名和拥有者；地址留空时使用 Git 用户名和工作空间名称。页面建议创建私有仓库，公开性和拥有者仍需在网页确认。软件不会静默创建、覆盖仓库或自动发布代码，创建不需要向软件提供 PAT。

在网页中登录后点击创建；不要初始化 README、`.gitignore` 或许可证，避免与现有本地提交产生不同历史。创建完成后把 SSH 仓库地址填回软件并验证、同步。已有仓库直接使用，不必重复创建。这个网页入口仅支持 GitHub，其他平台请先在对应网站创建仓库再填写地址。

### 远程操作超时

连接或读取仓库的超时为 120 秒；推送分支和版本标签默认允许 15 分钟，可以在“Git 账号”的“推送超时（分钟）”中设置为 1–60 分钟。设置仅保存到当前仓库的本地 Git 配置，不影响其他仓库。同步状态栏显示已等待时间，超时提示区分连接和推送阶段，并保留隐藏令牌后的 Git 最后输出。

超时会终止本次 Git 及其传输子进程，但不会删除本地提交、标签或版本文件。远程可能已经接收更新，因此不能把超时理解为远程必然未更新；恢复网络后再次点击“同步远程”即可检查并补齐，不要重新发布相同版本。读取成功也不代表上传链路正常；如果长时间没有进度，请检查本机网络、代理或 VPN，而不是反复增大时限。

### 失败后的补同步

- 发布始终先创建本地提交和版本标签。断网、认证失败、远程拒绝写入等情况不会回滚本地版本，也不会删除本地文件。
- 例如本地连续发布了 `v1.0.1`、`v1.0.2`、`v1.0.3`，即使三次推送全部失败，恢复网络后点击“同步远程”，或继续发布 `v1.0.4`，都会补齐当前分支的完整历史和所有相关版本标签，不只同步最后一个版本。
- 同步包含当前分支可达的全部 `v数字.数字.数字...` 标签，包括旧版轻量标签；不会发布其他分支或无关标签。重复同步不会创建重复提交或标签。
- 分支和标签使用原子推送：要么一起更新，要么全部拒绝。远程服务必须支持原子推送；不支持时保留本地版本并显示失败原因。
- 远程已有不同历史或同名但内容不同的标签时，软件不会强制覆盖，也不会自动拉取、合并。请先手动处理分歧，再点击“同步远程”。修改或删除已同步标签只影响本地，不会自动改写或删除远程标签。
- 远程同步上传完整 Git 提交历史，不仅是本次勾选的文件，也不只包含 ZIP 导出范围；同步前请确认历史中没有不应公开的内容。软件私有的版本清单和 CHANGELOG 仍保存在 `.git/code-version-manager/`，不会作为工作空间文件上传。

## 构建 0.1.8 安装包

构建脚本要求 `VERSION` 和 `debian/control` 中的版本号一致。执行以下命令同步版本号并打包：

```bash
cd /home/qm/Tool/code-version-manager
printf '0.1.8\n' > VERSION
sed -i 's/^Version:.*/Version: 0.1.8/' debian/control
sh build_deb.sh
```

生成的安装包为 `dist/code-version-manager_0.1.8_all.deb`。

先关闭正在运行的版本管理器，再卸载旧版：

```bash
sudo apt remove code-version-manager
```

在项目目录中执行以下命令安装或升级：

```bash
sudo apt install ./dist/code-version-manager_0.1.8_all.deb
```



安装前需要的软件和完整安装步骤请查看 [INSTALL.md](INSTALL.md)。
版本变更记录请查看 [CHANGELOG.rst](CHANGELOG.rst)。
使用 `apt install` 安装时，APT 会自动检查并安装缺少的必需依赖。

安装后从应用菜单打开 `Code Version Manager`。

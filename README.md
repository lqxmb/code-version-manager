# Code Version Manager（工作空间版本管理）

独立的 Git 图形版本管理器，可管理任意工作空间，支持本地离线发布和远程仓库同步。

主要功能：

- 为尚未使用 Git 的目录启用版本管理
- 工作空间位于其他 Git 仓库内时，仍可创建独立版本库
- 记录最近打开的 10 个工作空间，可从标题栏快速切换或清空记录
- 首次启用时只显示工作空间第一层，勾选目录会递归封装其内容
- 发布后续版本时同样只显示第一层，并记录所选目录内的删除
- 发布版本时自行勾选要封装的文件
- 配置 Git 提交姓名、邮箱和 SSH 远程仓库，支持生成或使用已有 SSH 密钥同步
- 发布后自动同步当前分支的完整提交历史和全部版本标签，也可手动点击“同步远程”
- 远程同步失败时保留本地版本；离线累积多个版本后，下次发布或手动同步会一次补齐
- 支持 `v0.0.1`、`v1.7.8.5`、`v1.7.8.9.7` 等多段版本号
- 版本历史按多段版本号从新到旧排序，不受文件日期影响
- 查看版本历史和版本标签
- 手动修改已发布版本的修改说明，并同步更新 Git 标签和 CHANGELOG
- 使用 Beyond Compare 比较两个完整版本目录
- 选择一个历史版本，使用 Beyond Compare 与完整当前工作空间比较并修改当前文件
- Beyond Compare 每次比较都加载软件内置的 `BCSessions.xml` 默认配置：按文件大小比较、关闭时间戳和内容快速比较、启用 Unicode 规范化，排除 `.git`、`*.zip` 和 `__pycache__`，目录树默认折叠
- 任意选择一个历史版本并下载为 ZIP，默认文件名为 `工作空间名_版本号.zip`（如 `m9_ws_v1.2.0.zip`）
- 删除所选版本标签，不改写提交历史或删除工作空间文件
- 删除 main 的最新版本及 Git 提交，分支退回上一提交并保留文件为当前修改
- 在窗口底部显示当前 Git 增量版本历史占用的磁盘空间
- 查看或下载自动生成的版本管理 `CHANGELOG.rst`，查看窗口支持一键最大化和还原
- CHANGELOG 使用标准 RST 标题格式，每行改动自动输出为 `* 内容`
- 工具元数据保存在 `.git/code-version-manager/`，不会污染工作空间根目录
- 在历史版本状态下阻止误提交
- 通过窗口标题栏的“关于”按钮查看当前软件版本

## Git 账号与远程同步

远程同步统一使用 SSH；本地仓库路径也可用于同步。配置界面包含 SSH 仓库地址、提交姓名、邮箱和自动同步选项，推送超时放在“高级设置”中。

1. 在 GitHub、Gitee、GitLab 或其他 Git 服务上先创建远程仓库，并确保 SSH 密钥所属账号具有写入权限。GitHub 可点击“Git 账号”中的“创建远程仓库（网页）”，在官方网页登录并确认创建。
2. 打开工作空间，点击“Git 账号”。软件优先填入该工作空间的 `origin` 地址，并将 GitHub 的 HTTPS 地址转换为 SSH。例如，本项目的地址为 `git@github.com:lqxmb/code-version-manager.git`。没有 `origin` 时，按工作空间目录名显示地址示例；请填写真实的 GitHub 账号或组织，确认远程仓库名，再填写提交姓名和邮箱。自定义 SSH 主机别名和端口按系统 SSH 配置使用。
3. 点击“SSH 公钥设置”复制本机 `.pub` 公钥。没有密钥时，可在此窗口输入邮箱和可选口令，点击“生成新的 SSH 密钥”；成功后直接复制新公钥，在 GitHub 中选择 `Authentication Key`、粘贴并保存。私钥保存在本机，不会显示或上传。
4. 按需勾选“发布版本后自动同步”，点击“保存并验证连接”。本地已有提交时会执行不上传版本的 Git 推送 dry-run；也可以只保存配置，离线发布后再手动同步。

提交姓名和邮箱仅用于记录作者，SSH 身份由系统密钥决定。仓库地址、作者信息和同步选项保存在当前工作空间的 Git 本地配置中，不修改其他仓库或全局配置。保存配置会更新当前仓库的 `origin` 并清除旧的单独推送地址，其他远程不受影响。尚未启用版本管理的工作空间会先创建独立本地仓库。

两个按钮的作用：

| 按钮 | 作用 | 结果反馈 |
| --- | --- | --- |
| 保存配置 | 保存当前工作空间的仓库地址、作者信息、同步和超时设置，不访问远程 | 状态栏提示已保存、尚未验证连接 |
| 保存并验证连接 | 先保存配置，再检查读取连接和推送权限，不上传版本 | 成功弹窗显示“连接及推送预检查通过”；失败弹窗显示原因 |
| 主窗口的“同步远程” | 实际上传当前分支的提交和可达版本标签 | 状态栏显示同步结果；失败弹窗显示原因 |

首次配置或修改地址、密钥后建议验证连接，无需每次发布前重复验证。尚无本地提交或正在查看历史提交时，只能检查读取权限，弹窗会显示“连接成功，推送尚未验证”。发布首个本地版本或返回工作分支后可再次验证。预检查通过后，正式同步仍需满足分支保护规则和服务端检查。

### SSH 密钥与连接

- 已有密钥时，直接在“SSH 公钥设置”中选择并复制公钥。不要上传或发送没有 `.pub` 后缀的私钥。
- 没有密钥时，直接在“SSH 公钥设置”中输入邮箱，点击“生成新的 SSH 密钥”。邮箱默认取自账号窗口中填写的提交邮箱，用作密钥备注；密钥口令可选，设置时需输入两次确认。软件调用本机 `ssh-keygen` 生成 Ed25519 密钥，默认保存在 `~/.ssh/id_ed25519` 和 `~/.ssh/id_ed25519.pub`，同名文件已存在时自动使用 `id_ed25519_cvm_数字`，不会覆盖已有文件。也可自行在终端执行 `ssh-keygen -t ed25519 -C "你的邮箱"`。
- 加密私钥需先用 `ssh-add ~/.ssh/id_ed25519` 解锁；使用自动生成的新文件名或自定义文件名时，也需先用 `ssh-add` 加载，界面会显示对应命令。口令只用于本次生成，不保存在配置中。软件不会改写系统 SSH 配置。
- 首次连接 GitHub 时，在终端运行 `ssh -T git@github.com`，核对官方主机指纹后确认，不要关闭主机密钥检查。显示 `Hi <账号>! You've successfully authenticated` 表示身份验证成功；该测试命令通常返回退出码 1。
- `Permission denied (publickey)` 表示需要检查公钥授权、SSH agent 或所选密钥；仓库写入被拒绝时还需检查该账号的仓库写权限和分支规则。修复后点击“同步远程”即可，无需重复发布本地版本。

### 远程还没有仓库

“创建远程仓库（网页）”会根据填写的 GitHub 地址预填仓库名和拥有者；地址留空时使用工作空间名称，拥有者在网页选择。页面建议创建私有仓库，公开性和拥有者仍需在网页确认。软件不会静默创建、覆盖仓库或自动上传文件。

在网页中登录后确认创建。请勿初始化 README、`.gitignore` 或许可证，避免与现有本地提交产生不同历史。创建完成后把 SSH 地址填回软件并验证、同步；已有仓库不必重复创建。此网页入口仅支持 GitHub，其他平台请先在对应网站创建仓库。

### 远程操作超时

连接、读取仓库和推送预检查的超时为 120 秒；实际推送分支和版本标签默认允许 15 分钟，可以在“Git 账号 → 高级设置：推送超时”中设置为 1–60 分钟。SSH 同步仍可能因大文件或网络缓慢长时间等待，因此仍保留此设置，一般使用默认值即可。设置仅保存到当前仓库的本地 Git 配置，不影响其他仓库。同步状态栏显示已等待时间，超时提示区分连接和推送阶段，并保留 Git 最后输出。

超时会终止本次 Git 及其传输子进程，但不会删除本地提交、标签或版本文件。远程可能已经接收更新，因此不能把超时理解为远程必然未更新；恢复网络后再次点击“同步远程”即可检查并补齐，不要重新发布相同版本。读取成功也不代表上传链路正常；如果长时间没有进度，请检查本机网络、代理或 VPN，而不是反复增大时限。

### 失败后的补同步

- 发布始终先创建本地提交和版本标签。断网、认证失败、远程拒绝写入等情况不会回滚本地版本，也不会删除本地文件。
- 例如本地连续发布了 `v1.0.1`、`v1.0.2`、`v1.0.3`，即使三次推送全部失败，恢复网络后点击“同步远程”，或继续发布 `v1.0.4`，都会补齐当前分支的完整历史和所有相关版本标签，不只同步最后一个版本。
- 同步包含当前分支可达的全部 `v数字.数字.数字...` 标签，包括旧版轻量标签；不会发布其他分支或无关标签。重复同步不会创建重复提交或标签。
- 分支和标签使用原子推送：要么一起更新，要么全部拒绝。远程服务必须支持原子推送；不支持时保留本地版本并显示失败原因。
- 远程已有不同历史或同名但内容不同的标签时，软件不会强制覆盖，也不会自动拉取、合并。请先手动处理分歧，再点击“同步远程”。修改或删除已同步标签只影响本地，不会自动改写或删除远程标签。
- 远程同步上传完整 Git 提交历史，不仅是本次勾选的文件，也不只包含 ZIP 导出范围；同步前请确认历史中没有不应公开的内容。软件私有的版本清单和 CHANGELOG 仍保存在 `.git/code-version-manager/`，不会作为工作空间文件上传。

## 构建 0.1.9 安装包

构建脚本要求 `VERSION` 和 `debian/control` 中的版本号一致。执行以下命令同步版本号并打包：

```bash
cd /home/qm/Tool/code-version-manager
printf '0.1.9\n' > VERSION
sed -i 's/^Version:.*/Version: 0.1.9/' debian/control
sh build_deb.sh
```

生成的安装包为 `dist/code-version-manager_0.1.9_all.deb`。

安装前先关闭正在运行的版本管理器。需要卸载旧版时可执行（直接升级无需卸载）：

```bash
sudo apt remove code-version-manager
```

在项目目录中执行以下命令安装或升级：

```bash
sudo apt install ./dist/code-version-manager_0.1.9_all.deb
```



安装前需要的软件和完整安装步骤请查看 [INSTALL.md](INSTALL.md)。
版本变更记录请查看 [CHANGELOG.rst](CHANGELOG.rst)。
使用 `apt install` 安装时，APT 会自动检查并安装缺少的必需依赖。

安装后从应用菜单打开 `Code Version Manager`。

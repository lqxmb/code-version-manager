# Code Version Manager（工作空间版本管理）

Python 3 + GTK 3 桌面 Git 管理器，支持任意工作空间、本地离线发布、分支开发、手动目录合并、ZIP 导出、SSH 当前分支同步和高级整仓覆盖。

## 界面与版本选择

- 调整主窗口大小后自动记住宽高，下次启动恢复；最大化状态也会记住，并保留最大化前的普通窗口大小。记录保存在用户级 `code-version-manager/settings.ini`，不随工作空间切换改变；没有有效记录时使用 1120 × 720 的默认大小。
- 最上方标题栏只放应用名称、关于和窗口控制；下方工作空间工具行提供打开、最近工作空间、刷新、Git 账号、设置和“高级操作”。整仓覆盖从“高级操作 → 高级整仓覆盖”进入。
- 可将一个本地文件夹拖到主窗口打开；只接受单个文件夹。文件、多项拖放、非本地路径或操作进行中会提示且不切换工作空间。
- 主要操作行从“发布版本”开始，随后是分支选择、新建分支、合并到 main 和删除分支；右侧显示当前分支的远程状态及同步按钮。悬停可查看完整状态和操作说明。
- 历史操作保持一行：范围、比较、删除版本、下载版本、修改说明、查看 CHANGELOG、下载 CHANGELOG。窗口较窄时可横向滚动该操作条。
- 比较按钮随选择变化：选一个版本显示“所选版本与当前”，选两个显示“比较所选版本”，未选择时禁用。Ctrl 多选和 Shift 范围选择最多保留最近选中的两个版本；选择第三个时取消最早选中的版本。取消后重新选中视为最新选择，一次选入多个时按列表顺序处理。重建历史或切换分支、工作空间后清空选择。删除、下载和修改说明只在单选时启用。
- 底部只显示单行简短状态，路径或长结果不会撑大主窗口。“日志”打开独立窗口，按时间倒序查看完整结果、恢复引用和路径，可选择文字或“复制全部”。操作进行中仍可查看日志，耗时更新不重复写入日志。
- 日志按工作空间区分，只在本次应用会话保存，每个工作空间保留最近 200 条；关闭日志窗口再打开仍可查看，退出应用后不保留。重要恢复路径可从日志复制另存。

## 一条清晰的开发流程

以 main 的 `v0.0.3` 为例：

1. 先切换到当前检出的 `main`，再在版本历史选择 `v0.0.3`，点击“新建分支”，输入 `branch1` 并确认基线。只能从 main 新建开发分支。
2. branch1 独立发布 `branch1/v0.0.3-beta.0.0.1`、`...2`、`...3`。main 可同时发布 `v0.0.4`、`v0.0.5`、`v0.0.6`，开发分支基线始终是 0.0.3。
3. 点击“合并到 main”。确认框显示最新 beta、目标 main 正式版本及双方提交。开发分支有晚于最新 beta 的提交时，先发布新的 beta。
4. 合并直接打开 Beyond Compare、Meld 或 KDiff3。左侧为 beta 只读副本，右侧为 main 编辑副本；按文件手动同步并保存，关闭对比工具后点击“完成合并”或“取消合并”。
5. **完成合并会把所选结果作为 main 的普通单父提交保存，不执行 Git merge、不发布、不创建任何 Tag。** 确认框默认勾选删除 branch1 及全部 beta 标签，可取消勾选保留。用户之后可另行发布正式版。
6. “删除分支”支持选择本地或 origin 的非 main 分支；检查远程后确认删除该分支及全部 beta 标签，不要求已合并或正式发布。删除其他分支不要求当前工作区干净；如果删除的是当前分支，仍需先能安全切换到 main。其他 worktree 正在使用的分支不能删除。默认只删本地；可勾选同时删除远程。只删本地后，列表保留 origin 条目，可之后单独删除。

新建分支也可选择 main 的其他历史正式版本，但必须先检出 main。切换分支要求工作区干净；main 有未提交、暂存或未跟踪修改时，先提交或另行保存这些修改再切换。合并只处理本地状态，不隐式下载或上传；需要以另一端为准时先切换相应分支同步。

### 手动目录合并

- 对比使用 beta 与 main 的完整 Git 树，不按 manifest 或 export-ignore 裁剪。特殊文件用只读说明展示，不跟随符号链接。
- 两侧 `.gitignore` 分别按 Git 规则解析并取并集；任一侧忽略的路径都会从两边隐藏，且软件拒绝将其写回。会话开始后忽略规则固定。
- 相同文件、VERSION、CHANGELOG.rst 和特殊文件受保护；只允许把有差异的普通文件从右侧编辑副本写入 main。未知路径、来源只读副本变化、链接替换和会话并发变化都会被拒绝。
- 副本保存在实际 Git 目录 `code-version-manager/merge-review/`。打开或取消不会改变工作区、暂存区、提交和分支；取消会删除本次对比副本。
- 关闭对比工具后，界面只显示“完成合并”和“取消合并”。完成时会校验会话并创建 main 普通提交；完成后按 main 最近的正式标签刷新本地 VERSION 和 CHANGELOG.rst。
- 完成确认默认勾选清理来源本地分支和全部 beta 标签。完成不会发布版本或创建标签；远程来源分支及 beta 可在“删除分支”中选择 origin 条目后确认删除。

## VERSION 和标签

- 工作空间根目录 `VERSION` 和 `CHANGELOG.rst` 是软件生成的本地文件，均加入 `.gitignore`，不进入新发布提交、manifest、ZIP 或新的远程发布快照。本项目自身的 `VERSION` 仍是独立的软件包版本。
- main 发布正式标签，例如 `v0.0.7`，本地 VERSION 显示 `0.0.7`；开发分支发布 beta 时显示未编码的分支名，例如 `feature/camera/v0.0.3-beta.0.0.1`。
- 切换本地或远程分支、创建分支、发布、完成合并、修改或删除标签及同步后，软件重新生成两个文件。当前 HEAD 有标签时采用该标签；否则沿第一父链取最近正式版或本分支 beta，尚无 beta 的开发分支使用固定正式基线。未发布提交继续显示最近已发布标签。
- 根目录 CHANGELOG 只包含当前分支可达的正式标签和本分支 beta，不混入其他开发分支 beta；内部 metadata CHANGELOG 保留全仓库版本历史。
- 没有已发布标签时删除过期 VERSION，并生成“尚无版本”的 CHANGELOG。符号链接、目录或特殊文件目标会被拒绝，不跟随链接覆盖其他文件。
- 已跟踪的旧 VERSION、CHANGELOG 在下一次发布时从新提交中移除，本地文件保留。旧提交不改写，整仓同步仍会传输旧历史；导出旧版本也会排除这两个根目录文件。
- 预发布实际 Git 标签为 `branches/branch1/v0.0.3-beta.0.0.3`；界面显示 `branch1/v0.0.3-beta.0.0.3`。分支名含斜线时会 URL 编码。
- 旧 `beta.1` 标签继续可读，新发布只生成 `beta.0.0.N`。旧分支多基线或与 main 没有共同历史时，会提示先检查/整仓同步或新建分支，不自动改名和重写历史。
- Git 标签是仓库级引用。GitHub 的 Tags/Releases 页面仍显示全仓库标签，选择网页分支不会隐藏其他分支的标签。

默认“本分支相关版本”显示本分支版本及可达的正式基线，继承的正式版本只读；“全部分支版本”用于查询其他分支版本。分支列表把本地和 origin 同名分支合成一行，当前分支仅用绿色标识，文字不再添加“当前”，例如 `main（本地+origin）`。

## 当前分支同步：明确选择一端作为准本

发布始终仅保存本地，不自动上传。日常同步只处理当前分支及所属版本标签、备注，允许按确认的方向覆盖和回退。

| 当前分支 | 同步范围 |
| --- | --- |
| main | main 和全部正式版本标签 |
| retreat_teb | retreat_teb 和它的全部 beta 标签 |
| start_matching | start_matching 和它的全部 beta 标签 |

- “覆盖本地”以 origin 为准更新本地；“覆盖远程”以本地为准更新远程。按钮悬停提示说明方向及当前分支范围。范围内允许新增、替换、回退，以及删除来源不存在的标签；其他分支及其标签、备注不受影响。
- 两人分别上传 retreat_teb 和 start_matching，不会因为本地另一个分支较旧或尚未下载而覆盖对方分支。不支持多人同时修改同一个分支的自动整合；方向选错仍会回退当前分支。
- 开发分支继承的正式基线不随本次上传/下载改写。首次连接空远程时先同步 main；两端 main 缺失或正式基线标签不一致时，先切换 main 核对同步，再同步开发分支。
- 同步 main 可改写正式标签；这可能影响其他开发分支的固定基线。版本号和提交时间只供核对，不能替代提交关系判断。
- 当前分支一致时日常按钮绿色禁用；其他分支存在差异不影响此状态。每次检查仍刷新完整 origin 分支列表，失败则清空远程选项。
- 确认窗口显示当前范围内的领先、落后、分叉、标签变化及删除；当前范围在确认后变化会停止操作，其他分支并发更新不影响此次同步。
- 上传使用原子推送和精确租约，服务端权限和保护规则仍可能拒绝写入；精确租约不能阻止已经确认的回退。
- 下载前保存暂存、未提交及未跟踪文件，可能被覆盖的忽略文件移到恢复目录。完成后可恢复修改，冲突不删除恢复点。
- 若远程已经删除当前开发分支，下载确认后会删除本地该分支并返回本地 main；本地 main 和正式标签不随此次下载更新。其他 worktree 占用本次要更新或检出的分支时停止。
- 恢复引用位于 `refs/code-version-manager/recovery/`，配置、版本清单和内部 CHANGELOG 备份位于实际 Git 目录 `code-version-manager/recovery/`。恢复资料仅保存在本机。
- 传输包含所同步引用可达的 Git 历史，范围不限于 ZIP 或本次勾选文件。manifest 不上传，缺清单的远程版本从完整 Git 树导出。

### 删除本地与远程分支

“删除分支”会在后台检查 origin，再弹窗确认。默认只删本地；同名远程分支存在时，可勾选同时删除远程分支及它的全部 beta 标签。连接失败仍可只删本地。只删本地后，分支列表保留 `retreat_teb（origin）`；再次点击“删除分支”可选此条目，单独删除远程分支及 beta。

远程删除前备份旧引用并重新检查。若确认后分支或 beta 变化，停止并要求刷新；实际删除使用原子推送及精确租约。两端无法组成一个共同事务：先删远程，成功后删本地；远程非超时错误保留本地；远程超时仍删除本地，并提示远程结果待确认。远程成功而本地失败时明确报告结果。main 不可通过此入口删除。

远程删除超时后，恢复连接并刷新或重新打开软件；若仍有 `retreat_teb（origin）`，可选择后重试删除。超时也可能发生在远程已删成功之后，刷新后条目可能已消失。

删除本地整个分支后，日常同步其他分支不会传播这次删除。合并完成后的来源清理也只影响本地，需要再显式删除 origin 分支。

### 高级整仓覆盖

“高级整仓覆盖”保留整个受管仓库以一端为准的功能。它会新增、替换和删除全部分支与版本标签，包括目标独有分支和共享正式标签；应核对完整差异后确认。来源必须有 main，非版本标签、其他 remote、stash 和恢复引用不参与。

超时可能发生在远程已经接收更新之后。不要重新发布同一版本，修复网络后刷新、核对再同步或删除。

## 工作空间与本地发布

- 为普通目录启用独立 Git 仓库，初始分支 main；位于父 Git 仓库中的目录仍可创建独立版本库。
- 最近工作空间最多保存 10 个，可单独移除或清空。默认启动顺序：环境变量 `CODE_VERSION_MANAGER_REPOSITORY`、上次保存目录、`~/catkin_ws`。
- 发布选择器只显示顶层文件和目录，勾选目录递归封装；已删除的顶层范围继续显示并可发布删除。
- 发布使用临时暂存区，保留未选择的已有暂存内容；当前忽略规则排除的历史文件会停止跟踪，本地文件保留。
- 根目录 CHANGELOG.rst 是发布说明输入和本地自动生成文件，不纳入提交、清单或 ZIP。发布时先读取匹配版本的已有说明；发布成功后按当前分支可见标签说明覆盖该文件。切换分支同样会覆盖，请先在发布窗口确认需要保留的说明。首次启用缺失时先创建说明模板。
- 新工作空间的 `.gitignore` 从独立文件 `data/workspace.gitignore` 复制，包含 Catkin 构建、日志、缓存、ZIP 和两个生成文件的规则。打包前可直接编辑此模板；deb 安装到 `/usr/lib/code-version-manager/workspace.gitignore`，程序从同一安装位置读取。
- 已有 `.gitignore` 保留自定义内容及换行格式，仅补齐 `/VERSION`、`/CHANGELOG.rst`；迁移规则随本次发布自动提交。旧分支尚未迁移时通过本地 Git 排除规则保持生成文件不干扰分支操作。修改模板只影响以后创建 `.gitignore` 的工作空间。
- 查看历史版本时禁止误发布；可返回最近工作分支。切换分支及新建分支需要干净工作区，且新建分支只能从当前检出的 main 发起，防止覆盖未跟踪或被忽略文件。

根目录 CHANGELOG.rst 可按以下格式提供发布说明；输入版本号匹配时自动载入，未匹配时保留编辑内容：

```rst
0.0.7 (2026-11-04)
------------------
* 合入 branch1 的开发结果
* 保留 main 的后续修改
```

最终说明以发布窗口内容为准。内部 CHANGELOG 从标签说明生成；发布后根目录 CHANGELOG.rst 会自动刷新，修改或删除标签、分支切换和同步后也会刷新根目录文件。“下载 CHANGELOG”根据版本历史范围选项生成内容：“本分支相关版本”仅导出当前分支可见的正式版本和 beta，“全部分支版本”导出本地仓库所有正式版和 beta；不自动获取远程标签。保存对话框默认打开当前工作空间，文件名为 `CHANGELOG.rst`，可修改目录和文件名；覆盖已有文件时确认，取消不写入。导出在后台执行，完成后显示实际保存路径。

## 比较、导出和历史管理

- 版本历史在“提交”右侧显示“备注”。双击备注格可填写多行文字，例如“测试中”“A 现场已更新，B 现场测试中”，也可清空；编辑框提供“测试中”“已更新现场”快捷填入。列表单行显示，悬停查看完整文字。
- 只允许编辑当前分支所属版本的备注：main 编辑正式版，开发分支编辑自己的 beta；其他版本双击可只读查看。main 上被开发分支共享的正式版本也允许编辑备注，不影响固定基线。
- 备注保存只更新本地。点击“覆盖远程”上传，其他电脑点击“覆盖本地”获取；日常同步仅处理当前分支所属版本及其备注，高级整仓覆盖包含全部备注。确认框显示两端内容，以所选来源覆盖，包括清空，不自动合并文字。只有备注变化时不切换分支、不暂存工作区修改。
- 备注独立保存在 `refs/notes/code-version-manager/remarks/<完整版本标签>`，支持现有 origin SSH 或本地远程，不需要额外服务。应用显式传输这些 Git notes；普通 `git clone` / 默认 push 不包含它们，可通过应用“覆盖本地”获取。两端需使用支持备注的新版应用，旧版应用不会同步备注。
- 编辑备注不改写代码提交、版本标签、修改说明或固定基线，不写入 CHANGELOG、manifest、ZIP 或工作树文件。修改标签说明后保留备注；标签指向另一提交后旧备注不套用。删除版本、撤回版本提交及删除分支时同时删除所属备注；现有同步和撤回恢复点保存被覆盖的备注引用。
- 比较两个历史版本的完整目录，或将一个历史版本与可编辑的当前工作区比较。
- 设置中选择 Beyond Compare、Meld、KDiff3，默认 Beyond Compare；对比工具须自行安装。
- Beyond Compare 每次加载内置 BCSessions.xml，历史目录比较按大小比较并排除 `.git`、ZIP、`__pycache__`；手动合并会话使用已过滤的隔离目录，历史输入保持只读。
- 导出完整 ZIP，文件名默认为 `工作空间名_版本号.zip`。有本地 manifest 时按封装清单导出，否则从完整 Git 树导出；两种情况均排除根目录 VERSION 和 CHANGELOG.rst。
- 可查看全仓库内部 CHANGELOG、按版本范围选项选择位置下载 CHANGELOG、修改标签说明、删除标签；正式标签被其他活动分支共享时禁止单独改写/删除。“删除分支”会删除所选非 main 本地分支及其 beta 标签。
- “删除版本及提交”支持 main 正式版和当前开发分支自己的 beta，所选标签必须指向当前 HEAD。确认框显示实际分支及回退提交；无法撤回时显示原因，仍可按条件“仅删除版本”。
- 撤回使当前分支退回唯一父提交，保留当前源文件及未跟踪文件。有暂存修改时保留整个原暂存区，被撤回提交的改动也成为暂存修改；无暂存修改时，被撤回的内容成为未暂存修改或未跟踪文件。撤回唯一 beta 后保留分支和固定正式基线，刷新 VERSION、CHANGELOG；无本地 manifest 也可操作。
- 历史中间提交、首个或多父提交、同提交存在其他标签、浅克隆、未解决冲突、未完成操作和其他 worktree 占用会阻止撤回。其他分支版本及继承的正式版本只读，共享正式标签仍禁止单独删除。
- 撤回前保存旧引用、配置、版本清单、内部 CHANGELOG 及原始 index；恢复资料位置会显示在结果中。确认后分支、标签或基线变化则停止；index 安装失败时尝试回滚引用，后续文件刷新失败会明确提示提交已撤回及恢复位置。
- 删除版本及撤回提交只改变本地。需要更新远程时，在同一分支点击“覆盖远程”，核对回退和标签删除清单后确认。“删除提交”表示移出当前分支历史，恢复引用等仍可保留该 Git 对象。
- 元数据位于实际 Git 目录的 `code-version-manager/`，包括 versions 清单、内部 CHANGELOG.rst 和 recovery；不作为工作区文件上传。

### 清空历史恢复文件

主窗口底部“版本存储”旁提供“清空恢复文件”。它清理当前工作空间实际 Git 目录的 `code-version-manager/recovery/` 中的历史备份，以及这些恢复点对应的应用恢复引用。点击后先在后台统计，再确认目录、可清理数量、备份文件占用及保留数量；清理后无法再使用已删除的历史恢复点。

含工作区 stash 或被移走的忽略文件的恢复点会保守保留，软件重启后仍受保护；无法判断是否已经恢复时也保留。符号链接、特殊文件及不属于应用格式的目录同样保留。只有 Git 恢复引用而没有该目录下备份的旧记录不参与本次清理。

清理不改变源文件、暂存区、分支、版本标签或用户 stash，允许当前工作区存在普通修改；正在操作或有未完成 Git／手动合并操作时不可清理。取消不删除，失败时报告成功、保留、失败及未处理数量和残留位置。显示的占用只统计备份文件；Git 对象不随此次操作强制回收，清理也不连接远程。

## Git 账号与 SSH

“设置”可以保存应用级 GitHub 账号（用户名或组织名）、默认提交姓名和默认提交邮箱；这些是新启用工作空间的默认值。打开已有仓库的“Git 账号”时，非空默认姓名和邮箱会分别预填；只有保存该窗口时才写入仓库，单独保存“设置”不会改变已有仓库。留空的身份字段沿用当前有效 Git 配置，Git 仍未配置时使用本机默认身份。

“Git 账号”配置当前工作空间的唯一 origin SSH 地址、提交姓名、邮箱、服务商及推送超时；本地绝对路径也可作为远程用于离线同步。服务商可选 GitHub 或 GitLab；GitLab 默认使用 gitlab.com，也可在高级设置指定自建实例 HTTPS 主机。服务商和实例配置保存在当前仓库本地 Git 配置中，不影响其他工作空间。修改服务商不会自动改写已有 origin，会提示服务商与可识别的 origin 不一致；需要切换仓库时请手动填写目标 SSH 地址。未设置 origin 时，GitHub 示例使用“设置”中的 GitHub 账号；GitLab 示例留出用户或嵌套组路径供填写。

1. 选择 GitHub 或 GitLab，并创建远程仓库。“创建仓库（网页）”只打开所选服务商的创建页面，需自行登录并确认；创建时不要初始化 README、.gitignore 或许可证。
2. 填写真实 SSH 地址，例如 `git@github.com:<账号>/<仓库>.git` 或 `git@gitlab.com:<组>/<子组>/<仓库>.git`。提交姓名和邮箱记录作者，SSH 密钥决定登录身份。
3. 使用对应服务商的“SSH 公钥设置”复制 .pub 公钥并授权，也可生成 Ed25519 密钥；已有同名密钥不覆盖，私钥不显示、不上传。
4. 首次连接在终端执行对应主机的 `ssh -T git@主机名` 并核对服务商或实例管理员公布的主机指纹；加密或自定义密钥用 ssh-add 加载。
5. “保存配置”只写本地；“保存并验证连接”执行读取及推送 dry-run，不上传版本。实际覆盖由两个同步按钮确认后执行。

软件默认 SSH 遇到明确的“网络不可达”时，会使用 IPv4 自动重试一次，保留主机指纹校验；自定义 `GIT_SSH_COMMAND` 保持原样。公钥选择、首次主机信任、IPv4 排查和 GitLab 受保护分支的处理步骤见 [INSTALL 常见问题](INSTALL.md#ssh-公钥和私钥如何选择)。连接验证通过后，实际覆盖仍可能被服务端保护规则拒绝。

读取和权限预检查限时 120 秒；传输默认 15 分钟，可设置 1–60 分钟。同步超时会清理本次传输子进程，保留本地版本和恢复点；勾选同时删除两端时，远程删除超时仍继续删除本地。读取成功不代表写入权限或正式推送一定通过。

## 开发、构建与安装

软件发行版本以本项目 VERSION 文件为准，不等同于工作空间的正式或 beta 标签。打包前可编辑 `data/workspace.gitignore` 定制新工作空间的默认忽略规则，无需修改 Python 代码。

```bash
# 完整测试和语法检查
python3 -m unittest discover -s tests -p 'test*.py'
python3 -m py_compile src/code_version_manager.py

# 只在隔离副本和临时远程中验证指定工作空间
# 当前分支末尾版本满足条件时，也验证撤回、文件保留及显式同步
python3 tests/verify_workspace_copy.py ~/branch_testing

# 从源码运行
python3 src/code_version_manager.py

# 生成 dist/code-version-manager_<VERSION>_all.deb
sh build_deb.sh

# 重装
sudo apt install --reinstall ./dist/code-version-manager_$(cat VERSION)_all.deb

# 先退出正在运行的软件，再安装或升级
sudo apt install ./dist/code-version-manager_$(cat VERSION)_all.deb

# 卸载
sudo apt remove code-version-manager
```

完整依赖与故障排查见 [INSTALL.md](INSTALL.md)。安装后从应用菜单打开 Code Version Manager，或执行 `code-version-manager`。

# 执行 PLAN_v0.5.7：缺陷修复与通用性优化

## 摘要

修复配置读写、文件选择、历史比较与 ZIP 导出、软件 Release 发布、后台任务生命周期等问题，继续使用现有单文件结构。

## 实施内容

1. **配置读写**
   - 关闭 INI 插值，原样保存含 `%` 的路径和身份。
   - 设置保存统一使用同目录临时文件、`fsync`、权限保留和原子替换。
   - 配置读取失败时使用默认值；保存时拒绝覆盖无法解析的已有配置，并报告原因。
   - 最近记录保存失败时继续加载工作空间，并向用户提示。

2. **文件选择与比较规则**
   - 移除对构建、安装和日志目录的固定排除；文件选择按工作空间实际 Git 忽略规则决定。
   - 已有仓库通过 Git 解析忽略规则；启用前用临时 Git 元数据解析当前 `.gitignore`，不在来源目录创建 `.git`。
   - 保留 Beyond Compare 当前对 ZIP 和 `__pycache__` 的隐藏规则，不修改其参数或内置配置。
   - 保留顶层分组和删除范围语义；继续由现有默认忽略模板管理新工作空间规则。

3. **历史物化与 ZIP 导出**
   - 比较左右快照使用独立临时目录，避免标签转义后的目录名碰撞。
   - 通过磁盘临时归档逐项处理历史内容；拒绝越界路径及硬链接、特殊成员，符号链接以只读说明展示。
   - 普通清单、空清单及无清单导出都先写临时 ZIP，再原子替换目标。
   - 导出前后验证目标类型；失败时保留已有文件并清理临时文件。继续过滤根目录生成文件。

4. **软件 Release 发布**
   - 通过现有 gh 授权调用二进制附件 API，保留附件原名并正确编码 `#`、空格和中文。
   - 准备前拒绝控制字符及反斜杠文件名；GitHub 返回名称不一致时报告实际结果并保留草稿。
   - 登录、创建仓库和发布分别检查对应 CLI 能力；严格验证远程发行及附件字段类型。
   - 发布按钮依据已有目标校验状态启用；发布附件大小使用独立常量，默认限制保持 512 MiB。

5. **后台任务与操作结果**
   - 普通后台操作期间阻止关闭主窗口；结果回调统一校验窗口存活、仓库实例和任务代次。
   - 校验合并记录的对象结构和必要字段；损坏记录禁止提交及写回，并保留安全取消入口。
   - 对引用已变更但后续元数据刷新失败的操作，报告已完成阶段、提交或引用 OID 和恢复位置。
   - linked worktree 存储统计纳入实际与共享 Git 目录，并按 inode 去重。

## 接口与文档

- 保持现有后端及 GTK 调用接口；仅按需增加配置保存、归档处理、附件上传和后台任务辅助方法。
- 按项目规则更新 `HELP.md`、`README.md` 和 `AGENTS.md`；Beyond Compare 配置保持原样。
- 保持 Python 3.8、Git 2.25、GTK 3 兼容，不增加第三方依赖。

## 验证与默认边界

- 补齐配置异常、Git 忽略规则、比较名称碰撞、恶意归档、符号链接、导出中断、附件原名、异常 API 数据、过期回调、损坏合并记录、刷新失败及共享存储统计的回归用例。
- 远程操作仅使用模拟接口和临时 bare 仓库。完成后运行完整 unittest、源码编译检查及 `git diff --check`，并确认 GTK 用例的实际执行情况。
- 不修改软件 `VERSION`，不创建标签、提交、真实 Release 或构建发行包；保留现有未跟踪的 `plan/` 内容。
